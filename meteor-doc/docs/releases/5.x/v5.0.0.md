# v5.0.0 (开发中)

5.x 是在保持已有接口设计的基础上全新重构的版本。

当前版本为 **@project.developmentVersion@**，尚未正式发布。

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>meteor</artifactId>
    <version>@project.developmentVersion@</version>
</dependency>
```

## 新增

- 增加 gRPC、gRPC-Web、Connect、Triple、Dubbo、Thrift、JSON-RPC、XML-RPC、SOAP、Hessian 和 ONC RPC 协议，支持对应原生 SDK 和跨语言调用。
- 支持 Java 注解、Proto、Thrift IDL、WSDL 等服务定义方式；gRPC、Connect、Triple 支持流式调用。
- 同一服务可通过多个协议发布，支持共用端口、独立端口和 HTTP 路径挂载。
- 增加 TLS、HTTPS、DTLS，以及服务端认证和双向证书认证。
- 增加 ZooKeeper、Nacos、JDBC 注册中心，以及 Dubbo 注册发现整合。
- 增加 XML 静态地址本，可在启动时加载并校验提供者地址。
- 增加独立 Web 控制台，提供服务查询、方法调试和治理；支持无头模式和远程控制台管理。
- 提供独立 Telnet 模块，支持连接密码认证，以及实例、服务、规则和元信息管理。
- 提供 Spring、Spring Boot、Hasor、Hasor Boot、Solon 整合，通过 `@MetAddress` 注入远程服务。

## 优化

- 内核可独立启动，应用通过 `MetConfiguration` 创建 `MetContext`，不再依赖 Hasor 容器。
- 网络传输改用 Neta，统一 TCP、UDP、HTTP 和 WebSocket 的连接管理。
- 服务发布时校验协议能力、方法映射和 HTTP 路径冲突，注册中心按实例保存实际发布的协议地址。
- 本地 API、注册中心 API、Telnet 和 Web 控制台共用服务治理能力。

## 修复

- 修复多协议服务选址时使用其他协议地址的问题。
- 修复注册发现丢失部分协议地址的问题。
- 修复 HTTP 响应完整接收后因连接关闭而被误判失败的问题。

## 不兼容更新

- **依赖和 API**：核心依赖由 `hasor-rsf` 改为 `meteor`，Java 包名改为 `net.hasor.meteor`，运行环境要求 JDK 17 或以上。旧 `Rsf*` API 需按[创建应用](../../guides/application/overview.md)调整。
- **序列化**：RSF 默认编码由 Hessian 改为 JSON。旧客户端、服务端不能仅升级一端并继续使用各自默认配置；使用旧编码时需同时确认两端的编码名称和实现。
- **服务发现**：注册中心的数据结构和管理接口重新设计，旧注册数据不能直接作为当前实例数据使用，接入方式见[服务发现](../../guides/discovery/about.md)。
- **治理规则**：分流规则改用 XML，不再执行旧 Groovy 规则，写法见[规则脚本](../../guides/governance/rule-syntax.md)。
